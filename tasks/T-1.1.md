# T-1.1 — Environnement Python de référence et production d'un `.ply`

Jalon : 1 · Prérequis : T-1.0 `validée` · Tier : 2 · ⛔ GATE : non

## Objectif
Faire tourner le SDK amont sur le Mac (MPS ou CPU) et produire pour une image de la galerie le
`.ply`, `_input.png` et `_camera.json` de référence.

## À lire (liste fermée, dans cet ordre)
- `plan/04-jalon1.md`
- `reference/idol-sdk/README.md` lignes 1-80 ; `reference/idol-sdk/idol/sample.py` (61 lignes) ;
  `reference/idol-sdk/idol/device.py` (17 lignes)

## Fichiers à créer / modifier
- `Scripts/reference/setup_venv.sh` — crée `.venv-ref` (Python 3.11, `pip install -e reference/idol-sdk`)
- `Scripts/reference/run_sdk.py` — `--image`, `--mode`, `--seed`, `--steps`, `--out` ; appelle
  `IdolPipeline.from_pretrained(<dossier local>)` avec `device` = `IDOL_DEVICE` ou `mps`
- `.gitignore` : rien à ajouter (`.venv-ref/` y est déjà)

## Étapes
1. `Scripts/link-references.sh` (crée `reference/`).
2. `Scripts/reference/setup_venv.sh`.
3. Encodeurs : `IdolPipeline` refuse de démarrer sans accès à DINOv3 (`require_encoder_access`).
   Tant que G-0 n'est pas tranchée : passer `image_encoders={"dinov3": <dossier Comfy local>}`
   **seulement si** Vincent a répondu B ou C ; sinon sauter l'étape 4 (le Jalon 1 n'en dépend pas :
   `real_fixtures.py` de T-1.5 charge les décodeurs seuls, sans encodeurs) et le journaliser.
4. `run_sdk.py --image reference/idol-sdk/assets/gallery/avocado.webp --steps 10 --out .local-runs/sdk/`.

## Validation (dans l'ordre, arrêt au premier échec)
1. `.venv-ref/bin/python -I -c "import idol; print('IDOL OK')"` → `IDOL OK`
2. `ls .local-runs/sdk/avocado.ply .local-runs/sdk/avocado_input.png .local-runs/sdk/avocado_camera.json` → les trois fichiers

## Critère de fin
`IDOL OK` ; les trois fichiers existent — ou, sans DINOv3, validation 1 seule et la mention
« passe SDK complète reportée à G-0 » dans le journal (la fiche reste `validée`).
